PRECISION FORMATS CONTRACT

Call require_precision_environment() once at program initialization before using
the helpers. It rejects non-binary32 representations, missing IEEE datatype
facilities, and incompatible integer storage, using IEEE_ARITHMETIC inquiries,
not exception-flag operations. Do not compile with -ffast-math or finite-only,
no-signed-zero, or NaN-discarding options.

BF16 is a 16-bit bit container stored in integer(int16), NOT a native real kind.
FP32 means IEEE binary32 stored in real(real32), or its integer(int32) bit image.
Integer bit images are native objects, not serialized file bytes.

bf16_bits_to_fp32_bits and bf16_bits_to_real32 preserve every bit, including the
sign of zero and signaling NaNs. Widening does not quiet a signaling NaN.
fp32_bits_to_bf16_bits and real32_to_bf16_bits round finite values to nearest,
ties to even. This includes signed underflow to zero, the subnormal/normal
boundary, and rounding maximum finite values to signed infinity.
For NaNs, preserve sign and the top seven payload bits and force BF16 bit 6
(the quiet bit) to one. Lower sixteen payload bits are discarded. A NaN whose
only payload is in the discarded bits still becomes a quiet NaN, not infinity.
This matches src-cpu/utils/bf16.h as read for this precursor.

The bit-image entry points perform no floating-point evaluation. Real wrappers
use TRANSFER only. Tests construct/inspect NaNs through integer images and
TRANSFER, never arithmetic, real comparisons, or floating NaN classifiers.
No arithmetic exception or NaN-payload preservation through later floating
arithmetic is promised. Callers must not use signaling-NaN data in arithmetic.

packed_q8_byte(word, byte_index) returns integer(int32) in 0..255 for index 0..3:
index 0 = bits 0..7; index 3 = bits 24..31. Negative packed words are valid.
This is unsigned byte extraction, not signed int8 quantization or dequantization.
Invalid indices ERROR STOP before any bit operation with a variable position.
No numeric conversion of an unsigned high-bit pattern to an out-of-range signed
integer is used. Bit images are assembled using IBITS, IBSET, and in-range INT.
Host byte order does not change this logical low-to-high packing contract.
There is deliberately no binary serialization API.

Groupwise q8 scale/bias dequantization, arithmetic precision, FMA contraction and
rounding boundaries remain UNSPECIFIED until the model's C reference is frozen.
Do not infer a groupwise formula or a fused operation from this module.

TEST SOURCES
src-fortran/precision_formats.f90 is standalone standard Fortran 2018: no C/Python linkage,
compiler extensions, third-party libraries, model data or inference kernels.
src-fortran/tests/precision_test_cases.f90 checks all 65536 BF16 images with explicit NaN quieting,
DO CONCURRENT conversions with per-index outputs, 256 combinations of boundary
q8 bytes, and 22032 FP32 images emitted by the independent existing C helper.
The C corpus spans both signs, all 256 exponents, seven selected upper fractions,
five rounding tails, 4096 deterministic xorshift images, and sixteen special
images. Oracle files have required version/count headers and footers; malformed,
missing, truncated or extra records are errors. Generated output is not source.
test_precision.f90 is the mandatory core driver: no IEEE_EXCEPTIONS import,
flag operations or flag-status claims. Optional test_precision_ieee.f90 runs the
same shared cases while checking support for, clearing and inspecting the IEEE
invalid, overflow and underflow flags. Neither driver duplicates numeric cases.
src-fortran/tests/bf16_oracle.c includes the existing bf16.h in place; it neither replaces
nor modifies it. The C executable is a test oracle ONLY.
src-fortran/tests/run_checks.sh runs each compiler's full positive checks, then requires
controlled nonzero exits with matching diagnostics for invalid-low/high indices,
missing/truncated/corrupted/nonhex oracle files, unexpected NaN/infinity outputs,
and extra data after the footer. Both drivers use this same rejection runner.
Fixtures and full logs stay in the selected compiler/driver output directory;
compiler module files never cross directories.

VALIDATION STATUS
Validated with PATH GFortran 16.1.0 and Flang 24.0.0git
(e8e9abb11b3d199d861900858a7b42dcaabe4de3)
on Darwin arm64. Both compilers independently pass the core and optional IEEE
tasks: each runs the same 65536/22032/256 checks and all nine rejection cases.
Only the optional IEEE task checks exception flags.
Pixi is the task runner; it uses these PATH tools without installing compiler packages.
Xcode/Apple clang compiles only the independent C oracle.

From the receiving repository root with the fortran-precision feature configured,
ensure build/fortran-precision exists, then run:
    pixi run -e fortran-precision precision-versions > build/fortran-precision/versions.log 2>&1
    pixi run -e fortran-precision precision-test > build/fortran-precision/tests.log 2>&1
Inspect both complete logs. The test DAG builds the oracle first, then at most
two Fortran compilers with separate module and output directories under
build/fortran-precision/<compiler>/core. Each checks directory contains its positive
and rejection logs. To opt in to exception-flag diagnostics, run separately:
    pixi run -e fortran-precision precision-ieee-test > build/fortran-precision/ieee-tests.log 2>&1
Inspect that complete log and build/fortran-precision/<compiler>/ieee/checks.
The verified GFortran toolchain emitted duplicate-rpath
linker warnings; no Fortran source diagnostics or Flang/C-oracle warnings remained.

LFortran core validation remains pending IBSET integration. IEEE exception-flag
work is deferred to https://github.com/lfortran/lfortran/issues/16342 and is not
a prerequisite for mandatory mathematical validation.
No whole-model, LFortran, Metal, GPU, groupwise q8-math or inference correctness
claim is made. This is a validated precision precursor, not a verified model port.
